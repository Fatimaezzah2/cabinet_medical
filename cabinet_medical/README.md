# Cabinet Medical

## Description

Cabinet Medical is a Laravel-based medical appointment management system that allows patients to book appointments and administrators to manage doctors, services, users, and appointment confirmations.

The application supports three roles:

- **Admin**: manages services, users, appointments, appointment statuses, and system overview.
- **Doctor**: views assigned appointments and updates appointment status.
- **Patient**: registers publicly, books appointments, views personal appointments, and cancels their own appointments.

- PHP 8.2+
- Composer
- MySQL

- NPM

## Installation

### Clone Repository

```bash
git clone <repository-url>
cd cabinet_medical
```

### Install Dependencies

```bash
composer install
npm install
```

### Environment Configuration

```bash
cp .env.example .env
php artisan key:generate
```

Configure your database in `.env`.

Example:

```env
DB_CONNECTION=mysql
DB_HOST=127.0.0.1
DB_PORT=3306
DB_DATABASE=cabinet_db
DB_USERNAME=root
DB_PASSWORD=
```

### Mail Configuration

Appointment confirmation emails require SMTP configuration.

Example:

```env
MAIL_MAILER=smtp
MAIL_HOST=smtp.example.com
MAIL_PORT=587
MAIL_USERNAME=your_smtp_username
MAIL_PASSWORD=your_smtp_password
MAIL_ENCRYPTION=tls
MAIL_FROM_ADDRESS="no-reply@example.com"
MAIL_FROM_NAME="${APP_NAME}"
```

With `MAIL_MAILER=log`, emails are written to `storage/logs/laravel.log` and are not sent to real inboxes.

### Run Migrations and Seeders

```bash
php artisan migrate --seed
```

### Build Frontend Assets

For development:

```bash
npm run dev
```

For production:

```bash
npm run build
```

### Start Development Server

```bash
php artisan serve
```

Application URL:

```txt
http://127.0.0.1:8000
```

## Appointment Confirmation Email Workflow

1. Patient creates an appointment.
2. Appointment status is initially `pending`.
3. Admin or doctor changes the appointment status to `confirmed`.
4. The system sends an `Appointment Confirmation` email to the patient.
5. If SMTP fails, the appointment remains confirmed and the error is logged.

Emails are only sent when the status changes from `pending` to `confirmed`.

## API Endpoints

Base URL:

```txt
/api
```

### Appointments

#### List Appointments

```http
GET /api/appointments
```

#### Create Appointment

```http
POST /api/appointments
```

Example request:

```json
{
  "patient_id": 5,
  "doctor_id": 2,
  "service_id": 3,
  "appointment_date": "2026-06-10 09:00:00",
  "notes": "First visit"
}
```

#### Show Appointment

```http
GET /api/appointments/{id}
```

#### Update Appointment

```http
PUT /api/appointments/{id}
```

#### Delete Appointment

```http
DELETE /api/appointments/{id}
```

This follows the application workflow and updates the appointment status to `cancelled`.

### Web Search Endpoint

```http
GET /appointments/search?search=keyword
```
